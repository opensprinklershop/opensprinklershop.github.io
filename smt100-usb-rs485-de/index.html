SMT100 über USB-RS485-Adapter am Raspberry Pi (OSPi)

Diese Anleitung beschreibt, wie ein Truebner SMT100 (RS485/Modbus-RTU) über einen USB-RS485-Adapter an eine OpenSprinkler-Installation auf einem Raspberry Pi (OSPi) angeschlossen und konfiguriert wird.

Verwandte Seiten: Analog Sensor Konfiguration, Sensor-Automation und Monitore.

Nur für OSPi / Linux

Der hier beschriebene USB-RS485-Weg gilt für die native OpenSprinkler-Version auf Raspberry Pi/Linux (Build mit -DOSPI). Auf ESP32/ESP8266 wird der SMT100 stattdessen über den I2C-RS485-Adapter oder das ASB angeschlossen.

Überblick

Auf dem OSPi verwendet OpenSprinkler libmodbus und spricht den SMT100 direkt als Modbus-RTU-Gerät über den seriellen Port des USB-Adapters an. Die Zuordnung ist:

  • RS485-Adapter → eine Zeile in der Datei rs485 (Geräteindex 0, 1, …)
  • Modbus-Slave-Adresse des SMT100 → Feld ID des Sensors
  • Messgröße (Feuchte / Temperatur / Permittivität) → Typ des Sensors

Die seriellen Parameter sind fest auf 9600 Baud, 8 Datenbits, gerade Parität (Even), 1 Stoppbit (8E1) eingestellt – genau die Werkseinstellung des SMT100.

Benötigte Hardware

  • Raspberry Pi mit laufender OpenSprinkler-OSPi-Firmware
  • USB-RS485-Adapter mit automatischer Senderichtungsumschalte (Auto-RTS/DE), z. B. auf Basis von CH340, CP2102 oder FT232 mit MAX485/MAX3485. Galvanisch getrennte Adapter (z. B. DSD TECH SH-U11, Waveshare USB-TO-RS485, USR-DR134) sind empfehlenswert.
  • Truebner SMT100 in der RS485-Variante
  • Stromversorgung für den SMT100: 3,6 – 20 V DC (kann meist aus dem 5 V/3,3 V des Pi bzw. einem separaten Netzteil bereitgestellt werden)

Verkabelung

Verbinden Sie die RS485-Datenleitungen des SMT100 mit dem Adapter und versorgen Sie den Sensor mit Spannung:

SMT100 (typische Truebner-Aderfarben) Funktion Anschluss
Braun + Versorgung (3,6–20 V) Netzteil / Pi 5 V
Weiß GND Netzteil-GND und Adapter-GND
Grün RS485 A (D+) Adapter A / D+
Gelb RS485 B (D−) Adapter B / D−

Aderfarben prüfen

Die Belegung kann je nach SMT100-Ausführung und Kabelcharge abweichen. Prüfen Sie immer das Datenblatt Ihres Sensors. GND von Sensor, Versorgung und Adapter müssen gemeinsam verbunden sein.

Busabschluss

Bei kurzen Leitungen und einem einzelnen Sensor ist meist kein 120-Ω-Abschlusswiderstand nötig. Bei langen Leitungen oder mehreren Geräten Abschluss an den Busenden vorsehen.

USB-Adapter am Raspberry Pi erkennen

Stecken Sie den Adapter ein und ermitteln Sie den Gerätepfad:

# nach dem Einstecken das Kernel-Log ansehen
dmesg | grep -i tty

# vorhandene USB-Serial-Geräte auflisten
ls -l /dev/ttyUSB*

Der Adapter erscheint üblicherweise als /dev/ttyUSB0.

Stabilen Gerätenamen verwenden

/dev/ttyUSB0 kann sich beim Neustart oder bei mehreren Adaptern ändern. Verwenden Sie stattdessen den stabilen Pfad unter /dev/serial/by-id/:

bash ls -l /dev/serial/by-id/

Der dort angezeigte Pfad (z. B. /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0) kann direkt in der rs485-Datei eingetragen werden und bleibt konstant.

Die Datei rs485 anlegen

OpenSprinkler liest beim Start die Datei rs485 aus seinem Arbeitsverzeichnis (der Installationsordner, in dem auch die .dat-Dateien liegen; bei der Systemd-Installation WorkingDirectory aus OpenSprinkler.service). Jede Zeile beschreibt genau einen Adapter.

Wechseln Sie in das OpenSprinkler-Verzeichnis und legen Sie die Datei an:

cd /pfad/zu/OpenSprinkler
echo "/dev/ttyUSB0" > rs485

Bei stabilem Namen:

echo "/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0" > rs485

Mehrere Adapter – ein Eintrag pro Zeile (Index beginnt bei 0):

/dev/ttyUSB0
/dev/ttyUSB1

Alternative: Modbus-TCP-Gateway

Statt eines seriellen Pfades kann in der rs485-Datei auch IP oder IP:Port stehen (z. B. 192.168.0.50:502). Dann spricht OpenSprinkler ein Modbus-TCP-Gateway an. Ohne Port wird 502 verwendet.

Da der OSPi-Dienst als root läuft, sind keine zusätzlichen Berechtigungen (Gruppe dialout) erforderlich. Wird OpenSprinkler manuell als normaler Benutzer gestartet, fügen Sie den Benutzer der Gruppe dialout hinzu:

sudo usermod -aG dialout $USER
# danach neu anmelden

OpenSprinkler neu starten

Die rs485-Datei wird nur beim Start ausgewertet:

sudo systemctl restart OpenSprinkler

Oder bei manuellem Betrieb den Prozess neu starten. Zur Kontrolle können die Logs (bei Debug-Build) den Verbindungsaufbau anzeigen; schlägt modbus_connect fehl, erscheint eine Connection failed-Meldung.

Sensor in der Benutzeroberfläche konfigurieren

Öffnen Sie Analog Sensor Konfiguration und legen Sie mit Sensor hinzufügen einen neuen Sensor an:

Feld Wert
Typ Truebner SMT100 RS485 Modbus, Feuchtemodus (bzw. Temperatur- oder Permittivitätsmodus)
Bus / RS485-Port Index des Adapters aus der rs485-Datei (erste Zeile = 0)
ID / Modbus-Adresse Slave-Adresse des SMT100 (Werkseinstellung meist 1)
Intervall Leseintervall in Sekunden, z. B. 60
Log / Anzeigen nach Bedarf aktivieren

Das Register wird automatisch aus dem Typ abgeleitet (Temperatur, Feuchte bzw. Permittivität) – es muss nicht von Hand eingestellt werden. Der gelesene Rohwert wird umgerechnet:

  • Feuchte: Rohwert / 100 → volumetrischer Wassergehalt in %
  • Temperatur: (Rohwert / 100) − 100 → °C
  • Permittivität: Rohwert / 100 → dielektrische Permittivität

Für Temperatur und Feuchte desselben Sensors legen Sie zwei Sensoreinträge mit gleichem Bus und gleicher ID, aber unterschiedlichem Typ an.

Alternative: Konfiguration über die REST-API

Der Sensor kann auch direkt über den /sc-Endpunkt angelegt werden (port = Adapterindex, id = Modbus-Adresse):

# Feuchte, Adapter 0, Modbus-Adresse 1, Intervall 60 s
curl "http://<ip>/sc?pw=<md5pw>&nr=1&type=1&group=0&name=SMT100-Feuchte&port=0&id=1&ri=60&enable=1&log=1"

# Temperatur desselben Sensors
curl "http://<ip>/sc?pw=<md5pw>&nr=2&type=2&group=0&name=SMT100-Temp&port=0&id=1&ri=60&enable=1&log=1"

Sensortypen: 1 = SMT100 Feuchte, 2 = SMT100 Temperatur, 3 = SMT100 Permittivität.

Modbus-Adresse eines SMT100 ändern

Neue SMT100 haben ab Werk üblicherweise die Adresse 1. Sollen mehrere Sensoren an einem Bus betrieben werden, muss jeder eine eigene Adresse erhalten.

Nur einzeln adressieren

Zum Setzen der Adresse verwendet OpenSprinkler den Broadcast (Adresse 253). Schließen Sie zum Adressieren immer nur einen Sensor an den Bus an, sonst reagieren alle gleichzeitig.

Über den /sa-Endpunkt kann dem Sensor mit der Nummer nr eine neue Modbus-Adresse id zugewiesen werden:

curl "http://<ip>/sa?pw=<md5pw>&nr=1&id=2"

Passen Sie danach das ID-Feld der Sensorkonfiguration an die neue Adresse an.

Mehrere Sensoren und mehrere Adapter

  • Mehrere SMT100 an einem Adapter: unterschiedliche Modbus-Adressen vergeben, alle Sensoreinträge mit gleichem Bus, aber verschiedenen IDs.
  • Mehrere Adapter: je einen Pfad pro Zeile in rs485; der Zeilenindex (0, 1, …) ist der Bus-Wert im Sensor.
  • Es werden bis zu MAX_RS485_DEVICES (16) Adapter unterstützt.

Fehlersuche

Problem Prüfen
Kein Messwert / data_ok bleibt aus A/B nicht vertauscht? GND gemeinsam verbunden? Richtiger Bus-Index und ID?
Connection failed im Log Gerätepfad in rs485 korrekt? Adapter eingesteckt (ls /dev/ttyUSB*)? Rechte (root/dialout)?
Sporadische Timeouts Leitungslänge/Abschluss prüfen, Versorgungsspannung des Sensors stabil?
Adresse lässt sich nicht setzen Nur ein Sensor am Bus während /sa?
Werte unplausibel Falscher Typ gewählt (Feuchte vs. Temperatur vs. Permittivität)?

Verbindung testen

Mit apt install libmodbus-dev steht auf dem Pi auch das Tool-Ökosystem von libmodbus bereit. Zur schnellen Prüfung des Busses eignen sich gängige Modbus-CLI-Werkzeuge (z. B. mbpoll): mbpoll -m rtu -b 9600 -P even -a 1 -t 4 -r 1 -c 1 /dev/ttyUSB0.
