SMT100 via USB-RS485 Adapter on Raspberry Pi (OSPi)

This guide explains how to connect and configure a Truebner SMT100 (RS485/Modbus-RTU) to an OpenSprinkler installation on a Raspberry Pi (OSPi) using a USB-RS485 adapter.

Related pages: Analog Sensor Config, Sensor Automation and Monitors.

OSPi / Linux only

The USB-RS485 path described here applies to the native OpenSprinkler build on Raspberry Pi/Linux (built with -DOSPI). On ESP32/ESP8266 the SMT100 is connected instead via the I2C-RS485 adapter or the ASB.

Overview

On OSPi, OpenSprinkler uses libmodbus and talks to the SMT100 directly as a Modbus-RTU device over the serial port of the USB adapter. The mapping is:

  • RS485 adapter → one line in the rs485 file (device index 0, 1, …)
  • Modbus slave address of the SMT100 → sensor ID field
  • Measurement (moisture / temperature / permittivity) → sensor Type

The serial parameters are fixed at 9600 baud, 8 data bits, even parity, 1 stop bit (8E1) — exactly the SMT100 factory setting.

Required hardware

  • Raspberry Pi running the OpenSprinkler OSPi firmware
  • USB-RS485 adapter with automatic transmit-direction control (auto-RTS/DE), e.g. based on CH340, CP2102 or FT232 with MAX485/MAX3485. Galvanically isolated adapters (e.g. DSD TECH SH-U11, Waveshare USB-TO-RS485, USR-DR134) are recommended.
  • Truebner SMT100 in the RS485 variant
  • Power supply for the SMT100: 3.6 – 20 V DC (usually available from the Pi's 5 V/3.3 V or a separate supply)

Wiring

Connect the SMT100 RS485 data lines to the adapter and provide power to the sensor:

SMT100 (typical Truebner wire colors) Function Connect to
Brown + supply (3.6–20 V) power supply / Pi 5 V
White GND supply GND and adapter GND
Green RS485 A (D+) adapter A / D+
Yellow RS485 B (D−) adapter B / D−

Verify wire colors

The pinout may vary depending on the SMT100 version and cable batch. Always check your sensor's datasheet. The GND of sensor, supply and adapter must share a common connection.

Bus termination

For short cabling and a single sensor, a 120-Ω termination resistor is usually not needed. For long cables or multiple devices, add termination at the bus ends.

Detect the USB adapter on the Raspberry Pi

Plug in the adapter and determine the device path:

# check the kernel log after plugging in
dmesg | grep -i tty

# list available USB serial devices
ls -l /dev/ttyUSB*

The adapter typically appears as /dev/ttyUSB0.

Use a stable device name

/dev/ttyUSB0 can change on reboot or when multiple adapters are present. Use the stable path under /dev/serial/by-id/ instead:

bash ls -l /dev/serial/by-id/

The path shown there (e.g. /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0) can be written directly into the rs485 file and stays constant.

Create the rs485 file

At startup OpenSprinkler reads the rs485 file from its working directory (the install folder that also contains the .dat files; with the systemd install this is the WorkingDirectory from OpenSprinkler.service). Each line describes exactly one adapter.

Change into the OpenSprinkler directory and create the file:

cd /path/to/OpenSprinkler
echo "/dev/ttyUSB0" > rs485

With a stable name:

echo "/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0" > rs485

Multiple adapters — one entry per line (index starts at 0):

/dev/ttyUSB0
/dev/ttyUSB1

Alternative: Modbus-TCP gateway

Instead of a serial path, the rs485 file may also contain IP or IP:port (e.g. 192.168.0.50:502). OpenSprinkler then talks to a Modbus-TCP gateway. Without a port, 502 is used.

Since the OSPi service runs as root, no additional permissions (group dialout) are required. If you start OpenSprinkler manually as a normal user, add the user to the dialout group:

sudo usermod -aG dialout $USER
# then log out and back in

Restart OpenSprinkler

The rs485 file is only evaluated at startup:

sudo systemctl restart OpenSprinkler

Or restart the process when running manually. For verification, the logs (in a debug build) show the connection setup; if modbus_connect fails, a Connection failed message appears.

Configure the sensor in the user interface

Open Analog Sensor Config and create a new sensor via Add sensor:

Field Value
Type Truebner SMT100 RS485 Modbus, moisture mode (or temperature or permittivity mode)
Bus / RS485 port index of the adapter from the rs485 file (first line = 0)
ID / Modbus address slave address of the SMT100 (factory setting usually 1)
Interval read interval in seconds, e.g. 60
Log / Show enable as needed

The register is derived automatically from the type (temperature, moisture or permittivity) — it does not need to be set manually. The raw value read is converted as:

  • Moisture: raw / 100 → volumetric water content in %
  • Temperature: (raw / 100) − 100 → °C
  • Permittivity: raw / 100 → dielectric permittivity

For temperature and moisture of the same sensor, create two sensor entries with the same Bus and same ID but different Type.

Alternative: configuration via the REST API

The sensor can also be created directly via the /sc endpoint (port = adapter index, id = Modbus address):

# Moisture, adapter 0, Modbus address 1, interval 60 s
curl "http://<ip>/sc?pw=<md5pw>&nr=1&type=1&group=0&name=SMT100-Moisture&port=0&id=1&ri=60&enable=1&log=1"

# Temperature of the same sensor
curl "http://<ip>/sc?pw=<md5pw>&nr=2&type=2&group=0&name=SMT100-Temp&port=0&id=1&ri=60&enable=1&log=1"

Sensor types: 1 = SMT100 moisture, 2 = SMT100 temperature, 3 = SMT100 permittivity.

Change the Modbus address of an SMT100

New SMT100 units usually ship with address 1. If several sensors share one bus, each must get its own address.

Address one at a time

To set the address, OpenSprinkler uses the broadcast (address 253). When addressing, connect only one sensor to the bus, otherwise all of them respond at once.

The /sa endpoint assigns a new Modbus address id to the sensor with number nr:

curl "http://<ip>/sa?pw=<md5pw>&nr=1&id=2"

Afterwards, update the ID field of the sensor configuration to the new address.

Multiple sensors and multiple adapters

  • Multiple SMT100 on one adapter: assign different Modbus addresses, all sensor entries with the same Bus but different IDs.
  • Multiple adapters: one path per line in rs485; the line index (0, 1, …) is the Bus value in the sensor.
  • Up to MAX_RS485_DEVICES (16) adapters are supported.

Troubleshooting

Problem Check
No reading / data_ok never set A/B swapped? GND commonly connected? Correct Bus index and ID?
Connection failed in the log Device path in rs485 correct? Adapter plugged in (ls /dev/ttyUSB*)? Permissions (root/dialout)?
Sporadic timeouts Check cable length/termination; is the sensor supply voltage stable?
Address cannot be set Only one sensor on the bus during /sa?
Implausible values Wrong Type selected (moisture vs. temperature vs. permittivity)?

Test the connection

With apt install libmodbus-dev the libmodbus tooling ecosystem is available on the Pi. For a quick bus check, common Modbus CLI tools (e.g. mbpoll) are useful: mbpoll -m rtu -b 9600 -P even -a 1 -t 4 -r 1 -c 1 /dev/ttyUSB0.
