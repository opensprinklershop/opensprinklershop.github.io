OpenSprinklerPro API- und Plattformergänzung

Diese Seite ist die vollständige deutsche Fassung der OpenSprinklerPro-API- und Plattformergänzung. API-Pfade und Parameter bleiben unverändert.

This addendum documents firmware endpoints and platform details that were added after the original 2.2.1 manual pages.

The OpenSprinklerShop firmware, including OpenSprinklerPro, uses its own firmware version numbering independent of upstream OpenSprinkler releases. Current OpenSprinklerShop firmware version: 2.4.0(229).

Plattformkorrekturen

Endpunkt Unterstützte Plattformen Hinweise
/uc, /uu, /us, /ub ESP32, ESP8266 Firmware online update and full backup endpoints. Not available on OSPi/Linux builds.
/sx ESP32, ESP8266, OSPi Sensor-only configuration backup/import. Distinct from /ub.
/jw ESP32, ESP8266, OSPi Monthly water-usage data.
/tg, /tl, /ta, /tc, /tx ESP32 HTTPS certificate and ACME/Let's Encrypt management.
/rk, /rp, /ru ESP32 with ENABLE_RAINMAKER ESP RainMaker status, provisioning and unlink/reset flows.
/jm, /mm ESP32 with ENABLE_MATTER Matter pairing information and commissioning window.
/bd, /bs, /bc ESP32 with OS_ENABLE_BLE BLE scan and discovered-device management.
/ir, /iw, /zj, /zs, /zg, /zd, /zo, /zc ESP32-C5 with Zigbee/IEEE 802.15.4 support Radio mode and Zigbee gateway/client endpoints.

Online-Update und Backup

Endpunkt Zweck
GET /uc?pw=... Check update manifest and report whether a newer firmware is available.
GET /uu?pw=... Start firmware update. Advanced parameters can override URLs and hashes: zu, mu, fu, zs, ms; vt selects zigbee or matter.
GET /us?pw=... Read update status and progress.
GET /ub?pw=... Export full controller configuration for app-side backup before update.

HTTPS-Zertifikate und ACME

Endpunkt Zweck
GET /tg?pw=... Read active certificate type, subject, issuer and validity.
POST /tl?pw=... Upload custom PEM certificate and key. Reboot afterwards.
GET /ta?pw=... Read ACME configuration and status.
POST /tc?pw=... Save ACME settings and optionally request a certificate.
GET /tx?pw=... Delete ACME data and return to the internal certificate.

RainMaker und Matter

Endpunkt Zweck
GET /rk?pw=... Read RainMaker status. Optional reset_mapping=1 or factory_reset=1 perform maintenance actions.
GET /rp?pw=...&uid=...&key=... Start RainMaker provisioning.
GET /ru?pw=... Unlink RainMaker account and trigger reset/reboot behavior.
GET /jm?pw=... Read Matter commissioning state, QR-code URL and manual pairing code.
GET /mm?pw=...&t=300 Open Matter commissioning window; t is optional timeout in seconds, max 900.

Wasserverbrauch und Sensoren

Endpunkt Zweck
GET /jw?pw=... Read monthly water usage: pulse rate, current month and stored records.
GET /sf?pw=... List supported sensor types for the current build.
GET /sx?pw=... Export/import sensor configuration only.
GET /mc, /ml, /mt Configure, list and discover monitor types.

Erweiterte Sensor-API (kompatibel zur offiziellen Firmware 2.2.1(5))

Die offizielle OpenSprinkler-Firmware 2.2.1(5) hat eine "Expanded Sensor"-API eingeführt. Die OpenSprinklerShop-Firmware ab 2.4.0(229) stellt dieselben Endpunkte als Fassade über ihr eigenes Sensorsystem bereit: Es gibt nur einen Sensorspeicher, die offizielle uuid ist die OpenSprinklerShop-Sensornummer nr, und die offizielle OpenSprinkler-App sowie Drittanbieter-Clients, die gegen die offizielle API geschrieben wurden, funktionieren unverändert. Die OpenSprinklerShop-Endpunkte (/sl, /sc, /so, /se, ...) arbeiten weiter auf denselben Daten.

Verfügbar auf ESP32, ESP8266 und OSPi. Die Endpunkt-Schlüssel haben drei Buchstaben.

Endpunkt Zweck
GET /jsn?pw=... Sensoren mit letztem Messwert auflisten (sn[], count). Schlüssel: uuid, name, type, unit, flag, status, interval (Minuten), min, max, value, extra.
GET /csn?pw=...&uuid=-1&type=... Sensor anlegen (uuid=-1 oder sid=-1) oder ändern. Allgemeine Parameter: name, min, max, interval, unit, flag. Typparameter: children/action (Aggregate), pin/subtype/scale/offset/points (ADS1115), action (Weather), metric (System Internal), input (Onboard Digital), ntype (Typ 5, siehe unten).
GET /dsn?pw=...&uuid=... Einen Sensor löschen; uuid=-1 löscht alle Sensoren.
GET /jsd?pw=... Sensorbeschreibungen für schemagesteuerte Editoren: sensors[] (Index = type), units[], enums, as, flags.
GET /jsl?pw=... Sensorprotokoll: [[uuid,ts,value],...]; fmt=csv oder fmt=binary; Filter uuid/sid, before, after, count, cursor; page=1 aktiviert die Slot-Paginierung mit den X-OS-*-Antwort-Headern.
GET /dsl?pw=...&uuid=... Protokolleinträge eines Sensors löschen (uuid=-1: gesamtes Protokoll). page=1 liefert das JSON-Fortschrittsobjekt; das Löschen wird in einer Anfrage abgeschlossen (done=1).
GET /jpa?pw=... Pro Programm die Wetter- (wa), Sensor- (sa) und Gesamt-Anpassungsfaktoren (ta) sowie maxrt.
GET /jp Jeder Programmeintrag trägt das Sensor-Anpassungsobjekt {flag,uuid,splits[]} als 8. Element ({}, wenn keines).
GET /cp?...&snadj=flag,uuid,x0,y0,... Sensor-Anpassung des Programms setzen; snadj=0,0 entfernt sie. v bleibt Pflicht.
GET /mp?...&usa=0|1 Manueller Programmstart mit (1) oder ohne (0) Sensor-Anpassung. Ohne usa bleibt das OpenSprinklerShop-Verhalten erhalten und die Anpassung wird angewendet.

Typzuordnung (/jsn.type, Index von /jsd.sensors):

type Offizieller Name OpenSprinklerShop-Sensoren
0 Aggregate Sensorgruppen MIN/MAX/AVG/SUM sowie die neuen MEDIAN (1004) / RANGE (1005). children sind die Gruppenmitglieder; scale/offset der Kinder müssen 1/0 sein.
1 ADS1115 Analog-Sensor-Board-Typen (10, 11, 12 stückweise, 15-18, 30-32, 49) und OSPi-ADC-Typen (50-53). pin 1-16 = Board-Adresse 0x48-0x4B x Kanal 0-3. Subtypen: 0 Linear, 1 Stückweise (neuer Typ 12), 10/11 SMT50, 12/13 SMT100 analog, 15 VH400, 16 THERM200, 17 AquaPlumb. scale/offset werden nach der Umrechnung angewendet.
2 Weather Wetterdienst-Sensoren (101-110); action indiziert enums.WeatherAction.
3 System Internal Freier Speicher (metric 0), freier Flash (1), CPU-Temperatur (3).
4 Onboard Digital Neuer Typ 56: entprellter Zustand von SN1 (input 0) oder SN2 (input 1).
5 OpenSprinklerShop-Sensor Alle übrigen Typen (RS485, MQTT, Zigbee, BLE, FYTA, Gardena, Remote, Durchflussmesser, ...). extra.ntype ist der OpenSprinklerShop-Typ; typspezifische Einstellungen werden mit /sc bearbeitet.

Verhaltenshinweise:

  • min/max begrenzen den Sensorwert, wenn sie mit /csn gesendet werden (gespeichert als cmin/cmax/clamp in sensors.json); status meldet Bit 3/4, wenn ein Wert begrenzt wurde. Mit /sc angelegte Sensoren werden nicht begrenzt und melden ihren natürlichen Bereich.
  • interval ist in Minuten; das OpenSprinklerShop-ri ist in Sekunden und wird in /jsn auf volle Minuten gerundet.
  • Fest verdrahtete Subtypen melden ihre native Einheit; eine andere Einheit derselben Gruppe (z. B. Fahrenheit) wird abgelehnt, weil die Firmware keine Einheiten umrechnet.
  • Programm-Anpassungen: Eine snadj-Kurve mit zwei Punkten wird zu einer PROG_LINEAR-Anpassung, eine Zwei-Punkt-Stufe zu PROG_DIGITAL_MIN, andere Kurven nutzen den neuen Anpassungstyp PROG_PIECEWISE (5). /jp meldet die erste Anpassung eines Programms; weitere mit /sb definierte Anpassungen wendet der Scheduler weiterhin an.
